# ZIP-PICK 웹사이트 소개 보고서

## 1. 서비스 개요

ZIP-PICK은 사용자의 주거 예산, 최소 전용면적, 통근 가능 시간, 출발 시간, 대중교통 혼잡도를 종합하여 거주 후보 매물을 추천하는 부동산 탐색 웹서비스이다. 단순히 가격이나 위치만 기준으로 매물을 나열하는 방식에서 벗어나, 실제 생활 조건에 가까운 기준으로 매물의 적합도를 비교하는 것을 목표로 한다.

본 서비스는 서울 지역 실거래 기반 매물 데이터와 대중교통 경로 정보를 결합한다. 사용자는 직장 또는 학교 주소를 입력한 뒤, 자신이 감당 가능한 예산과 생활 조건을 설정하면 조건에 맞는 매물을 지도와 카드 목록에서 확인할 수 있다. 또한 각 매물별 대중교통 경로, 소요 시간, 환승 횟수, 교통 혼잡도, 추천 점수를 함께 제공하여 주거 선택 과정에서 필요한 정보를 한 화면에서 비교할 수 있도록 구성하였다.

## 2. 개발 배경

청년층과 1인 가구는 주거지를 선택할 때 가격뿐 아니라 통근시간, 대중교통 접근성, 출퇴근 혼잡도, 최소 생활 면적 등을 함께 고려한다. 그러나 기존 부동산 탐색 서비스는 매물 자체의 가격, 면적, 위치 정보 제공에 집중되어 있어 실제 출퇴근 경험이나 생활 부담을 반영한 비교가 제한적이다.

ZIP-PICK은 이러한 문제를 보완하기 위해 다음과 같은 질문에서 출발하였다.

- 내가 감당할 수 있는 금액 안에서 어떤 매물이 가장 현실적인 선택인가?
- 같은 가격대라면 어느 매물이 더 짧고 덜 혼잡한 통근 경로를 제공하는가?
- 전세, 월세, 매매처럼 거래 방식이 다른 매물을 하나의 기준으로 비교할 수 있는가?
- 특정 지역의 거래가 상대적으로 활발한지 지도에서 직관적으로 파악할 수 있는가?

이를 통해 ZIP-PICK은 단순 검색형 부동산 서비스가 아니라, 통근과 생활 조건을 반영한 의사결정 보조형 주거 추천 서비스로 기획되었다.

## 3. 주요 사용자

ZIP-PICK의 주요 사용자는 직장 또는 학교를 중심으로 거주지를 탐색하는 사람이다. 특히 자취를 시작하는 대학생, 사회초년생, 직장인, 신혼부부처럼 예산 제약과 통근 조건을 동시에 고려해야 하는 사용자를 주요 대상으로 한다.

사용자는 부동산 전문 지식이 많지 않아도 본인의 생활 조건을 입력하는 방식으로 추천 결과를 얻을 수 있다. 가격, 면적, 통근시간, 혼잡도 등 서로 다른 정보를 추천 점수와 카드 UI로 정리하여 비교 부담을 줄이는 것이 서비스의 핵심 방향이다.

## 4. 핵심 기능

### 4.1 생활 조건 기반 매물 추천

사용자는 직장 또는 학교 주소, 최대 예산, 최소 전용면적, 최대 통근시간, 출발 시간을 입력한다. 서비스는 입력 조건을 바탕으로 후보 매물을 1차 필터링하고, 대중교통 경로 계산이 필요한 매물만 선별하여 추천 결과를 제공한다.

추천 방식은 두 가지로 구성된다.

- 전체 금액 추천: 매매, 전세, 월세를 하나의 예산 기준으로 비교한다. 월세는 보증금에 1년치 월세를 더한 방식으로 환산하여 비교한다.
- 거래유형별 상세 추천: 매매, 전세, 월세 중 사용자가 원하는 거래 방식을 선택하고 해당 방식에 맞는 세부 금액 조건을 입력한다.

### 4.2 추천 점수 제공

각 매물은 가격 적합도, 통근시간 적합도, 면적 적합도, 혼잡도 적합도를 종합하여 추천 점수로 표시된다. 추천 점수는 사용자가 여러 매물을 빠르게 비교할 수 있도록 돕는 지표이다.

카드에는 추천 점수와 함께 다음 정보가 제공된다.

- 주소 및 건물명
- 거래유형 및 가격
- 전용면적
- 통근시간
- 평균 혼잡도
- 추천 사유
- 경로 확인 버튼

### 4.3 대중교통 경로 시각화

추천 매물의 경로 확인 버튼을 누르면 해당 매물에서 목적지까지의 대중교통 경로가 지도에 표시된다. 지하철은 노선 색상에 맞춰 시각화하고, 버스는 간선, 지선, 광역 등 버스 유형에 맞는 색상으로 표현한다.

경로 확인 상태에서는 선택된 매물의 출발지와 목적지만 강조되며, 다른 매물 핀은 일시적으로 숨겨진다. 이전으로 버튼을 누르면 추천 목록과 매물 핀이 다시 표시된다.

### 4.4 교통 혼잡도 반영

서비스는 지하철 및 버스 혼잡도 데이터를 활용하여 경로별 평균 혼잡도와 최대 혼잡도를 표시한다. 사용자는 같은 통근시간이라도 상대적으로 덜 혼잡한 경로를 선택할 수 있다.

지하철 혼잡도는 노선과 시간대 정보를 기준으로 반영하며, 버스 혼잡도는 정류장별 시간대별 승하차 인원 정보를 기반으로 추정한다. 실제 실시간 차내 혼잡도와는 차이가 있을 수 있으므로 서비스에서는 추정 혼잡도임을 안내한다.

### 4.5 서울 자치구 거래활동 단계구분도

검색 전 기본 화면에서는 서울 25개 자치구의 최근 3개월 거래량을 기준으로 거래활동 단계를 표시한다. 거래가 상대적으로 활발한 지역은 진한 색으로, 상대적으로 낮은 지역은 연한 색으로 표현한다.

단계는 서울 내 상대 분위 기준으로 5단계로 구분된다.

- 81~100%
- 61~80%
- 41~60%
- 21~40%
- 0~20%

마우스를 자치구 위에 올리면 해당 구의 최근 3개월 거래량 정보를 확인할 수 있다. 이를 통해 사용자는 검색 전에 서울 전역의 부동산 거래 흐름을 직관적으로 파악할 수 있다.

### 4.6 지도 보조 요소

지도에는 방위표와 축척을 표시하여 사용자가 현재 지도의 방향과 거리감을 파악할 수 있도록 하였다. 기본 화면은 서울 전역을 볼 수 있는 축척으로 설정되어 있으며, 검색 및 경로 확인 시에는 결과 위치에 맞춰 지도가 자동 조정된다.

실거래 원천 자료는 최근 6개월 기준 447,798건이며, 이 중 좌표 매칭과 서비스 검색 조건에 맞춰 검색용 후보군을 정제하였다.

### 5.1 최근 6개월 실거래가 데이터

부동산 매물 후보군은 최근 6개월 서울 지역 실거래가 데이터를 기반으로 구성하였다. 원천 데이터는 2025년 12월부터 2026년 5월까지의 거래 자료이며, 총 447,798건의 거래 자료를 수집하였다. 이 중 주소와 좌표가 매칭된 자료를 선별하고, 서비스에서 검색 가능한 형태로 정제하여 15,756건의 검색용 매물 데이터를 구축하였다.

데이터는 매매와 전월세 자료를 함께 포함하며, 월세 매물은 보증금과 월세를 별도로 저장한다. 전체 금액 추천 모드에서는 월세를 `보증금 + 월세 × 12` 방식으로 환산하여 매매, 전세, 월세를 하나의 예산 기준에서 비교할 수 있도록 하였다. 이는 사용자가 1년 동안 실제로 부담해야 하는 금액을 직관적으로 반영하기 위한 방식이다.

### 5.2 ODsay 대중교통 API

ODsay 대중교통 API는 출발지와 목적지 사이의 실제 대중교통 경로를 계산하는 데 사용한다. API를 통해 총 소요시간, 도보 거리, 환승 횟수, 교통수단별 세부 경로, 지하철 및 버스 노선 정보를 가져온다.

ZIP-PICK은 ODsay API를 단순히 모든 후보 매물에 호출하지 않는다. API 호출량 제한과 응답 속도를 고려하여, 예산과 면적 조건을 통과한 매물 중 목적지와의 거리 및 사전 점수를 기준으로 실제 경로 계산 후보를 줄인다. 이후 선별된 후보에 대해서만 ODsay API를 호출하여 추천 결과를 만든다.

### 5.3 교통 혼잡도 데이터

혼잡도는 지하철과 버스를 구분하여 반영한다. 지하철은 평일 출근 시간대 노선별 혼잡도 자료를 사용하며, ODsay 경로에서 반환된 지하철 노선명, 역 목록, 구간 시간을 기준으로 평균 혼잡도와 최대 혼잡도를 계산한다.

버스는 서울시 버스 노선별, 정류장별, 시간대별 승하차 인원 자료를 기반으로 추정한다. ODsay 경로에서 반환된 버스 번호와 승하차 정류장을 서울시 버스 노선 데이터와 매칭하고, 해당 시간대의 정류장별 누적 탑승 추정값을 이용하여 구간 평균 혼잡도와 최대 혼잡도를 계산한다. 현재 버스 혼잡도 데이터는 2025년 4월 자료를 기반으로 하며, 총 657개 버스 노선 정보를 포함한다.

## 6. 추천 방식

추천 과정은 다음 순서로 진행된다.

1. 사용자가 목적지와 생활 조건을 입력한다.
2. 예산과 거래유형 조건으로 1차 후보 매물을 필터링한다.
3. 목적지와의 직선거리를 기준으로 대중교통 경로 계산 후보를 줄인다.
4. ODsay API를 통해 실제 대중교통 경로를 조회한다.
5. 통근시간, 환승, 혼잡도, 면적, 가격 적합도를 계산한다.
6. 추천 점수를 기준으로 결과를 정렬하여 지도와 카드 목록에 표시한다.

대중교통 API 호출량을 줄이기 위해 캐시와 안전 호출량 제한을 적용하였다. 같은 출발지와 목적지 조합은 캐시를 활용하며, 일정 거리 이내의 가까운 목적지는 도보 경로로 처리하여 불필요한 API 호출을 줄인다.

### 6.1 추천 점수 산정 방식

추천 점수는 사용자의 생활 조건에 대한 매물의 적합도를 100점 기준으로 환산한 지표이다. 현재 추천 점수는 다음 네 가지 요소를 가중합하여 계산한다.

| 평가 요소 | 가중치 | 의미 |
| --- | ---: | --- |
| 금액 적합도 | 35% | 사용자가 입력한 예산과 매물 가격이 얼마나 잘 맞는지 평가 |
| 통근시간 적합도 | 35% | ODsay API로 계산된 실제 대중교통 소요시간이 사용자의 최대 통근시간 조건에 얼마나 부합하는지 평가 |
| 면적 적합도 | 20% | 사용자가 입력한 최소 전용면적 조건을 얼마나 충족하는지 평가 |
| 혼잡도 적합도 | 10% | 출근 시간대 경로의 평균 혼잡도가 낮을수록 높은 점수 부여 |

금액 적합도는 단순히 가장 싼 매물을 높게 평가하는 방식이 아니라, 사용자가 입력한 예산에 얼마나 가까우면서도 과도하게 초과하지 않는지를 평가한다. 전체 금액 추천 모드에서는 월세 매물의 경우 `보증금 + 월세 × 12`를 기준 금액으로 사용하여 매매, 전세, 월세를 한 줄에서 비교한다.

통근시간 적합도는 직선거리 기반 추정 시간이 아니라, 최종 추천 결과에서는 ODsay API가 반환한 실제 대중교통 소요시간을 기준으로 산정한다. 면적 적합도는 최소 면적을 충족하면 기본 점수를 확보하고, 조건보다 넉넉한 면적일수록 추가 점수를 받을 수 있도록 설계하였다. 혼잡도 적합도는 평균 혼잡도가 낮을수록 높은 점수를 부여한다.

### 6.2 혼잡도 산정 방식

혼잡도는 사용자가 단순히 빠른 경로만 선택하지 않고, 출근 과정의 체감 부담까지 고려할 수 있도록 제공하는 보조 지표이다.

지하철 혼잡도는 ODsay API의 지하철 구간 정보와 내부 혼잡도 데이터를 결합하여 계산한다. 경로에 포함된 지하철 노선, 정차역, 구간별 시간을 확인한 뒤 각 구간의 혼잡도를 시간 가중 평균 방식으로 계산한다. 따라서 오래 머무르는 혼잡 구간은 평균 혼잡도에 더 크게 반영된다.

버스 혼잡도는 실시간 차내 혼잡도 API가 아니라, 서울시 승하차 인원 데이터를 활용한 추정값이다. 버스 노선의 정류장 순서와 시간대별 탑승 추정량을 기반으로, 사용자가 실제로 타는 승차 정류장부터 하차 정류장까지의 구간 평균 및 최대 혼잡도를 계산한다. 이 값은 실제 차량별 혼잡도와 완전히 동일하지는 않지만, 특정 시간대와 노선 구간의 상대적인 혼잡 경향을 파악하는 데 활용할 수 있다.

### 6.3 ODsay API 호출 절감 검색 알고리즘

ODsay API는 일일 호출량 제한이 있기 때문에, 모든 매물에 대해 경로를 계산하면 서비스가 빠르게 한도에 도달할 수 있다. ZIP-PICK은 이를 방지하기 위해 단계적 후보 축소 알고리즘을 적용하였다.

1. 사용자의 예산과 거래유형 조건으로 1차 후보를 걸러낸다.
2. 최소 전용면적 조건을 적용하여 생활 조건에 맞지 않는 매물을 제외한다.
3. 목적지 좌표와 매물 좌표의 직선거리를 계산한다.
4. 직선거리 기반의 대략적인 통근시간과 금액, 면적 조건으로 사전 점수를 계산한다.
5. 반경을 1km, 2km, 3km, 5km, 8km, 12km, 20km, 35km, 60km 순서로 넓히며 후보를 탐색한다.
6. 각 반경 안에서 사전 점수가 높고 목적지에 가까운 매물을 우선 선택한다.
7. 최종적으로 최대 20개 후보에 대해서만 ODsay API로 실제 대중교통 경로를 계산한다.
8. 실제 경로 결과를 반영해 통근시간, 혼잡도, 추천 점수를 다시 계산하고 상위 결과를 제공한다.

이 방식은 단순 무작위 샘플링이 아니라, 목적지와 가까운 매물을 먼저 살피되 가격, 면적, 통근 조건까지 함께 고려하는 방식이다. 따라서 API 사용량을 줄이면서도 사용자가 실제로 관심을 가질 가능성이 높은 매물을 우선 검토할 수 있다.

추가로 동일한 출발지와 목적지 조합은 `odsay_path_cache.json`에 저장하여 재사용한다. 하루 API 안전 호출량은 기본 900건으로 제한하며, 병렬 경로 계산은 최대 3개로 제한하여 API 과다 호출을 방지한다. 출발지와 목적지가 700m 이내인 경우에는 ODsay API가 대중교통 경로를 반환하지 않는 경우가 있으므로, 해당 경우는 도보 경로로 처리하여 불필요한 오류와 API 호출을 줄인다.

## 7. 화면 구성

ZIP-PICK의 화면은 크게 세 영역으로 구성된다.

### 7.1 좌측 검색 패널

좌측 패널에서는 목적지 주소, 추천 방식, 예산, 면적, 통근 기준, 출발 시간을 입력한다. 사용자가 부동산 용어에 익숙하지 않아도 이해할 수 있도록 입력 항목은 생활 조건 중심의 문구로 구성하였다.

### 7.2 중앙 지도

중앙 지도는 추천 매물의 위치, 경로, 자치구 거래활동 단계구분도, 축척, 방위표를 표시한다. 검색 전에는 서울 전역의 거래활동을 보여주고, 검색 후에는 추천 매물 위치와 경로를 중심으로 시각화한다.

### 7.3 우측 결과 패널

우측 패널은 추천 매물 목록과 경로 상세 정보를 표시한다. 추천 결과 화면에서는 정렬 기준을 선택할 수 있으며, 경로 확인 화면에서는 소요시간, 도보거리, 환승 횟수, 혼잡도, 세부 이동 구간을 확인할 수 있다.

## 9. 기대 효과

ZIP-PICK은 사용자가 주거지를 선택할 때 고려해야 하는 여러 조건을 하나의 화면에서 비교할 수 있도록 한다. 이를 통해 다음과 같은 효과를 기대할 수 있다.

- 가격 중심의 매물 검색에서 생활 조건 중심의 추천으로 확장
- 통근시간과 혼잡도까지 반영한 현실적인 주거지 비교

- 지역별 거래활동을 지도에서 직관적으로 파악
- 공공데이터와 민간 API를 결합한 부동산 의사결정 지원
